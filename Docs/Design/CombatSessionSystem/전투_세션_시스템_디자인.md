## 🎮 비전: "살아있는 전장"

### 당신이 보게 될 것

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
           메인 전투 (플레이어 포함)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

    [당신]  ⚔️  [강력한 적]
    
    HP: ████████░░  80/100
        
    검술 선택: 섬광베기 | 방패막기 | 회전베기 | 찌르기


┌─────────────────────────────────────────────┐
│  보조 전투 1        보조 전투 2              │
│  ┌─────────┐       ┌─────────┐              │
│  │동료 NPC │       │동료 NPC │              │
│  │   ⚔️    │       │   ⚔️    │              │
│  │적 부하  │       │  대기중 │              │
│  └─────────┘       └─────────┘              │
└─────────────────────────────────────────────┘
```

**상상해보세요:**
- 플레이어는 강력한 적과 결투 중
- 옆에서 동료 NPC가 적의 부하와 싸우는 중
- 또 다른 동료는 차례를 기다리며 대기
- 동료가 패배하면? 다음 동료가 자동으로 투입
- 동료가 승리하면? 플레이어를 지원
- **하나의 전장, 여러 개의 전투, 하나의 운명**

## 💡 핵심 개념

### 1. Combat Session (전투 세션)

**하나의 전투 "사건"**

```
예시: "산적 무리와의 조우"

A팀 (플레이어 일행)     B팀 (산적단)
├─ [플레이어]            ├─ [산적 우두머리]
├─ [검객 동료 NPC]       ├─ [산적 부관]
└─ [궁수 동료 NPC]       └─ [산적 졸개]
```

**Session의 책임:**
- 전체 전투의 시작과 종료
- 팀 구성 관리
- Battle 생성 및 매칭
- 승패 판정 (한쪽 팀 전멸 시)
- 보상 분배

---

### 2. Battle (개별 전투)

**두 Character의 1:1 결투**

```
Battle #1 (메인)
┌────────────────────────┐
│  [플레이어]             │
│      ⚔️                 │
│  [산적 우두머리]         │
└────────────────────────┘

Battle #2 (보조)
┌────────────────────────┐
│  [검객 동료]            │
│      ⚔️                 │
│  [산적 부관]            │
└────────────────────────┘

Battle #3 (보조)
┌────────────────────────┐
│  [궁수 동료]            │
│      ⚔️                 │
│  [산적 졸개]            │
└────────────────────────┘
```

**Battle의 책임:**
- 2명의 Character 1:1 전투 진행
- 턴제 전투 로직 실행
- 승패 판정 (한쪽 HP 0)
- Session에게 결과 보고

---

### 3. 동시 진행과 매칭

**같은 시간, 다른 공간**

```
시간축 ─────────────────────────────────────▶

Battle #1  ████████████████████░░░░  (진행 중)
Battle #2  ████████░░░░░░░░░░░░░░░░  (진행 중)
Battle #3  ███████████████████████░  (진행 중)
           ↑
         동시 진행
```

**매칭 규칙:**
1. 인원이 많은 팀부터 1명씩 배정
2. 상대가 없으면 Reserve (대기)
3. 전투 종료 시 재매칭

```
초기 매칭 (3 vs 2)
├─ A1 vs B1  ✅
├─ A2 vs B2  ✅
└─ A3 (대기)

A2 패배! (A1 전투 중, B2 승리)
├─ A1 vs B1  ← 계속 진행 중
└─ A3 vs B2  ← 새 매칭!
```

---

### 4. 승패 판정 규칙 ⭐

**Session의 즉시 종료 조건**

```
패배 판정:
└─ 플레이어(아군 선두) 전투 불능 → 즉시 패배!

승리 판정:
└─ 상대 팀 선두(보스) 전투 불능 → 즉시 승리!
```

**엔트리 고정 규칙:**
```
아군 팀 엔트리:
[0] 플레이어 (선두, 고정)  ← 절대 변경 불가
[1] 동료 NPC 1
[2] 동료 NPC 2
...

적군 팀 엔트리:
[0] 보스 (선두, 고정)  ← 절대 변경 불가
[1] 부하 1
[2] 부하 2
...
```

**중요 특성:**
- ✅ 플레이어는 항상 아군 팀 선두
- ✅ 상대 팀 선두는 항상 보스 (핵심 적)
- ✅ 선두 전투 불능 = 전투 즉시 종료
- ❌ 플레이어/보스는 엔트리 변경 불가

**전략적 의미:**
```
"보스를 쓰러뜨려야 승리"
"플레이어가 쓰러지면 즉시 패배"
"동료들은 플레이어를 지키기 위해 싸운다"
"부하들은 보스를 지키기 위해 싸운다"
```

---

### 5. 엔트리 순서와 매칭

**매칭 우선순위:**
```
1순위: 선두 vs 선두 (플레이어 vs 보스)
2순위: 나머지 순차 매칭

예시 (3 vs 3):
├─ Battle 1 (Main): 플레이어 vs 보스
├─ Battle 2 (Sub):  동료1 vs 부하1
└─ Battle 3 (Sub):  동료2 vs 부하2
```

**재매칭 시:**
```
동료1 패배 → Reserve 투입

Battle 1 (Main): 플레이어 vs 보스 (계속)
Battle 2 (종료): 동료1 패배
Battle 3 (계속): 동료2 vs 부하2

Reserve 없음 → Battle 2 재생성 안 됨
부하1은 합류할 Battle이 없기 때문에 대기 상태가 되며, 자신의 패시브 능력을 발휘함. (자기 팀의 보스를 강화하는 등)
```

## 🏗️ 시스템 계층

### Layer 1: CombatSessionManager (지휘관)

**"전장의 전체를 보는 자"**

```
역할:
- 전투 세션 생성 및 종료
- 팀 구성 관리
- 전투 매칭 알고리즘
- 전체 승패 판정
- 보상 계산 및 분배

사고 방식:
"누가 누구와 싸워야 할까?"
"전투가 끝났는데 다음 상대는?"
"전장이 정리되었는가?"
```

---

### Layer 2: Battle (전투 인스턴스)

**"두 검사의 결투"**

```
역할:
- 1:1 전투 진행
- 턴 관리
- 애니메이션 연출
- 승패 판정
- 결과 보고

사고 방식:
"이번 턴은 누구 차례?"
"공격이 명중했는가?"
"누가 이겼는가?"
```

---

### Layer 3: BattleExecutor (전투 로직)

**"검의 궤적을 계산하는 자"**

```
역할:
- 턴제 전투 로직
- 데미지 계산
- 상태 변화 처리
- 애니메이션 트리거

사고 방식:
"공격 타이밍은?"
"데미지는 얼마?"
"중단되었는가?"
```

## 🎬 시나리오로 보는 시스템

### 시나리오: "숲 속의 매복"

```
플레이어 일행이 숲을 지나가던 중
산적 두목과 부하 2명이 매복!

플레이어: "검을 뽑아라!"
동료 NPC: "제가 하나 맡겠습니다!"
```

**1. Session 시작**
```csharp
CombatSessionManager.StartSession(
    teamA: ["Player", "NPC_Ally"],           // 플레이어(선두) + 동료
    teamB: ["Bandit_Boss", "Bandit_1", "Bandit_2"]  // 두목(선두) + 부하 2명
);
```

**2. 초기 매칭 (엔트리 순서 기반)**
```
Session: "2명 vs 3명... 선두 우선 매칭"

Battle #1 (Main): Player(선두) vs Bandit_Boss(선두)  ← 최우선!
Battle #2 (Sub):  NPC_Ally vs Bandit_1
Reserve B팀:      Bandit_2 (대기 중)

⚠️ 플레이어 vs 보스는 항상 Battle #1 (Main)
```

**3. 전투 진행**
```
Battle #1: 플레이어와 산적 우두머리의 긴장감 넘치는 대결
  - 메인 카메라
  - 플레이어 입력
  - 큰 화면

Battle #2: 동료 NPC와 산적 부하의 전투
  - 작은 화면 (구석)
  - BT vs BT
  - 자동 진행
```

**4. Battle #2 종료 (동료 패배!)**
```
Session: "NPC_Ally 패배! A팀 Reserve 없음, B팀 Reserve 있음"
        "Bandit_2 투입!"

Battle #1 (Main): Player vs Bandit_Boss (계속)  ← 핵심 전투!
Battle #3 (신규): Bandit_1 vs Bandit_2?

⚠️ 아군 Reserve 없음
⚠️ 플레이어 혼자 vs 보스 (동료 지원 불가)
```

**5. Battle #1 종료 - 두 가지 결말**

**결말 A: 플레이어 승리!**
```
Battle #1: Player vs Bandit_Boss → Player 승리!

Session: "보스 전투 불능!"
        "💥 즉시 승리! 💥"
        
⚠️ 부하들(Bandit_1, Bandit_2)이 아직 살아있어도 즉시 승리!
→ 보스가 쓰러지면 끝!

보상:
├─ 골드: 500 (보스 처치)
├─ 경험치: 200
└─ 전리품: [산적 두목의 검], [두목의 투구]
```

**결말 B: 플레이어 패배...**
```
Battle #1: Player vs Bandit_Boss → Player 전투 불능!

Session: "플레이어 전투 불능!"
        "💀 즉시 패배! 💀"
        
⚠️ 동료들이 아직 싸우고 있어도 즉시 패배!
→ 플레이어가 쓰러지면 끝!

패널티:
├─ 골드: -50 (치료비)
└─ 경험치: 0
```

## 🎯 설계 철학

### 1. "보는 재미"

**플레이어는 항상 중심**
- 플레이어 포함 전투 = 메인 카메라
- NPC들의 전투 = 보조 화면 (옆에서 진행)
- 상황 파악 = 전략적 사고

**예시:**
```
"동료가 밀리고 있어! 내가 빨리 끝내야 해!"
"동료가 이기고 있네, 여유롭게 가자"
```

---

### 2. "전략의 깊이"

**팀 구성이 곧 전략**
```
3 vs 3 전투

전략 A (균형): 전사, 검객, 궁수 vs 적들
전략 B (집중): 강한 전사 1명 vs 약한 적 3명 (1:3!)
전략 C (시간차): 빠른 검객으로 먼저 승리 → 2:1 유리한 상황
```

---

### 3. "확장성"

**지금: 1:1**
```
Battle
├─ Character A
└─ Character B
```

**다음: 1:1 여러 개**
```
Session
├─ Battle 1
├─ Battle 2
└─ Battle 3
```

**향후: 다대다 (진영전)**
```
Session
├─ Frontline: 3 Battles (전선)
├─ Midline: 2 Battles (중간)
└─ Backline: 궁수들 (지원)
```

## 🔮 게임플레이 상상

### 시나리오 1: "혼자서는 안 돼!"

```
플레이어 Lv.5 vs 산적 두목 Lv.10

1:1이면 플레이어 패배 확정

하지만:
플레이어 + 동료 2명 vs 산적 두목

전략:
1. 동료들이 먼저 산적 두목과 번갈아 싸움
2. 산적 두목의 HP를 깎음
3. 플레이어가 마지막에 결정타!

→ 레벨 차이를 전략으로 극복!
```

---

### 시나리오 2: "시간 싸움"

```
플레이어 vs 적 보스 (강함, 시간 오래 걸림)
동료 vs 적 부하 (약함, 빨리 끝남)

동료 승리!
↓
2 vs 1 상황 (플레이어 + 동료 vs 보스)
↓
보스는 2명을 상대해야 함 (번갈아 전투)
↓
체력 소모 → 플레이어 승리!
```

---

### 시나리오 3: "피할 수 없는 선택"

```
아군 3명 vs 적군 5명 (수적 열세!)

전투 시작:
├─ A1 vs B1
├─ A2 vs B2
├─ A3 vs B3
└─ Reserve: B4, B5 (대기 중)

만약 A측이 빨리 이기지 못하면?
→ Reserve가 계속 투입됨
→ 아군은 쉴 틈 없이 연속 전투
→ 체력 소모 → 패배

전략적 선택:
1. 빠른 속공으로 수를 줄인다
2. 도망친다 (Session 중단)
3. 방어 위주로 버틴다 (지원군 기다림)
```

## 🧩 시스템 구조 개념

### 전투의 3단계

```
1단계: Session 생성
  "누구와 누가 싸우는가?" (팀 구성)

2단계: Battle 매칭
  "1:1로 어떻게 묶을까?" (매칭 알고리즘)

3단계: Battle 실행
  "검을 휘두르고, 막고, 피하고" (전투 로직)
```

---

### 데이터 흐름

```
[입력] TestScene: "산적 무리와 전투!"
  ↓
[설정] CombatSessionManager.StartSession(
         teamA: ["Player", "Ally1"],
         teamB: ["Bandit1", "Bandit2", "Bandit3"]
       )
  ↓
[매칭] MatchingAlgorithm
  ├─ Battle 1: Player vs Bandit1 (Main)
  ├─ Battle 2: Ally1 vs Bandit2 (Sub)
  └─ Reserve: Bandit3
  ↓
[실행] BattleExecutor
  ├─ Battle 1: 턴제 진행... (플레이어 입력)
  └─ Battle 2: 턴제 진행... (BT vs BT)
  ↓
[결과] Battle 1 종료 → Player 승리!
  ↓
[재매칭] Ally1 vs Bandit3 (Battle 3 생성)
  ↓
[종료] 모든 Battle 종료 → Session 종료
  ↓
[보상] SessionResult
  ├─ 승리: true
  ├─ 골드: 300
  ├─ 경험치: 150
  └─ 전리품: [...]
```

## 🌟 왜 이게 재밌는가?

### 1. 전략적 깊이

**단순한 레벨 차이를 전략으로 극복**
- 약한 캐릭터 여러 명 = 강한 캐릭터 1명
- 순서, 타이밍, 조합이 중요
- "어떻게 싸울까?"에 대한 고민

---

### 2. 몰입감

**살아있는 전장**
- 옆에서 들리는 검 부딪치는 소리
- 동료의 비명, 승리의 환호
- "나만 싸우는 게 아니다"

---

### 3. 긴장감

**시간과의 싸움**
- 동료가 위험하다
- 빨리 끝내야 한다
- 하지만 조급하면 실수한다
- **선택의 무게**

---

## 🎯 설계 목표

### 1. 확장성

```
현재: 1:1 전투 (Player vs Enemy)
  ↓
1단계: 1:1 일반화 (NPC vs NPC 지원)
  ↓
2단계: 다대다 (여러 Battle 동시 진행)
  ↓
3단계: 진영전 (대규모 전투)
```

**각 단계마다 시스템 재작성 없이 확장**

---

### 2. 명확한 역할 분리

```
CombatSessionManager
└─ "누가 누구와 싸우는가" (전략)

Battle
└─ "어떻게 싸우는가" (전술)

BattleExecutor
└─ "검이 어떻게 움직이는가" (연출)
```

**각 계층이 독립적**

---

### 3. 몰입감 유지

```
전투 중:
├─ 메인 Battle: 플레이어가 직접 플레이
├─ 서브 Battle: 눈으로 확인 (자동 진행)
└─ Session 상태: 전체 전황 파악

→ "내가 이 전장의 일부다"
```
