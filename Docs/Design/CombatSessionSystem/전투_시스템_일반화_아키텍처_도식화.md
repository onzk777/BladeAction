## 시스템 개요

### 일반화 목표
- **Player vs NPC**: 기존 기능 유지
- **NPC vs NPC**: 신규 기능 추가
- **슬롯 기반 공통 로직**: 코드 중복 제거
- **BattleExecutor 분리**: 코드 구조 개선

### 핵심 설계 원칙
- **슬롯 기반 시스템**: `CombatantSlot`을 통한 통합 관리
- **책임 분리**: `CombatManager`(상태 관리) vs `BattleExecutor`(실행 로직)
- **인터페이스 기반**: `ICombatController`를 통한 플레이어/AI 통합

## 주요 클래스 역할

### 1. CombatManager
**역할**: 전투 시스템의 중앙 관리자

**주요 책임**:
- 전투 초기화 및 종료 관리
- Actor 생성 및 배치
- InputHandler 생성 및 바인딩
- 전투 상태(BattleState) 관리
- BattleExecutor 생성 및 실행

**핵심 메서드**:
- `StartBattle()`: 전투 시작, 캐릭터 초기화, Actor 생성
- `RestartBattle()`: 전투 재시작
- `EndBattle()`: 전투 종료 처리
- `BindInputHandler()`: 슬롯 기반 InputHandler 바인딩
- `ResetNPCProbabilities()`: NPC 확률 리셋
- `ResetBehaviorTreeStates()`: BT 상태 리셋

**접근성**:
- 싱글톤 패턴 (`Instance`)
- 많은 멤버가 `internal`로 설정되어 `BattleExecutor`에서 접근 가능

---

### 2. BattleExecutor
**역할**: 전투 실행 로직 전담

**주요 책임**:
- 전투 루프 실행 (TeamA → TeamB 순환)
- 턴 수행 및 턴 전환 관리
- 히트 판정 완료 대기
- 피해량 계산 및 적용

**핵심 메서드**:
- `RunBattle()`: 전투 루프 메인 코루틴
- `PerformTurn()`: 단일 턴 수행 (약 460줄)
- `EnsureAllHitJudgmentsCompleted()`: 모든 히트 판정 완료 대기
- `ProcessDamageCalculation()`: 피해량 계산 및 적용

**설계 특징**:
- `CombatManager`보다 하위 계층
- `CombatManager`의 `internal` 멤버에 접근하여 상태 관리
- 별도 파일로 분리되어 코드 가독성 향상

---

### 3. BattleState
**역할**: 현재 전투 상태 저장소

**주요 책임**:
- 현재 턴 컨텍스트 저장
- 공격자/방어자 슬롯 및 컨트롤러 참조
- 입력 상태 (PerfectInput, InputTime)
- 히트 판정 상태 추적
- 전투 종료 상태 관리

**핵심 프로퍼티**:
- `CurrentTurnContext`: 현재 턴 컨텍스트
- `CurrentAttackerSlot` / `CurrentDefenderSlot`: 현재 공격자/방어자 슬롯
- `CurrentAttackerController` / `CurrentDefenderController`: 현재 컨트롤러
- `HitJudgmentCompleted[]`: 히트별 판정 완료 상태
- `ProjectileLaunched[]`: 히트별 발사체 발사 상태

**설계 특징**:
- `CombatManager` 내부 중첩 클래스
- `internal` 접근성으로 `BattleExecutor`에서 접근 가능
- 전투 상태의 단일 소스(Single Source of Truth)

---

### 4. CombatCharacterManager
**역할**: 전투 참가자 캐릭터 관리

**주요 책임**:
- 전투 참가자 ID 관리
- Character 인스턴스 참조 관리
- 슬롯 구조 생성 및 관리
- Controller 바인딩 관리

**핵심 메서드**:
- `InitializeBattle()`: 전투 초기화, 슬롯 생성
- `GetLeaderSlot()`: 팀 리더 슬롯 조회
- `GetSlotByInstanceId()`: ID로 슬롯 조회
- `EnumerateAllSlots()`: 모든 슬롯 열거

**슬롯 구조**:
- `TeamA` / `TeamB`: 팀별 슬롯 리스트
- 각 슬롯은 `Character`와 `Controller`를 바인딩

---

### 5. CombatantSlot
**역할**: 개별 전투 참가자 정보 캡슐화

**주요 책임**:
- Character 인스턴스 참조
- Controller 인스턴스 참조
- 팀 정보 및 리더 여부 관리

**핵심 프로퍼티**:
- `InstanceId`: 캐릭터 인스턴스 ID
- `Character`: Character 인스턴스 참조
- `Controller`: ICombatController 인스턴스 참조
- `Team`: 소속 팀 (TeamA/TeamB)
- `IsLeader`: 리더 여부
- `SlotControlType`: 제어 타입 (Player/AI)

**설계 특징**:
- `CombatCharacterManager` 내부 중첩 클래스
- 슬롯 기반 시스템의 핵심 데이터 구조
- Player/NPC 구분 없이 통합 관리

---

### 6. ICombatController
**역할**: 컨트롤러 인터페이스 (플레이어/AI 통합)

**주요 책임**:
- 커맨드 선택 인터페이스 정의
- 결과 수신 인터페이스 정의
- 애니메이션 제어 인터페이스 정의

**핵심 메서드**:
- `GetSelectedCommandIndex()`: 선택된 커맨드 인덱스 반환
- `GetSelectedCommand()`: 선택된 커맨드 데이터 반환
- `ReceiveCommandResult()`: 턴 결과 수신
- `OnPlayActionCommand()`: 공격 애니메이션 재생
- `OnPlayDefence()`: 방어 애니메이션 재생

**구현 클래스**:
- `PlayerController`: 플레이어 입력 기반
- `AIController`: Behavior Tree 기반 AI

---

### 7. BaseInputHandler
**역할**: 입력 처리 공통 로직

**주요 책임**:
- PerfectTimingWindow 관리
- 입력 리스닝 공통 로직
- 플레이어/AI 입력 통합 처리

**핵심 메서드**:
- `BindToSlot()`: 슬롯에 바인딩
- `RegisterHitTiming()`: 히트 타이밍 등록
- `HasPerfectInput()`: 완벽 입력 여부 확인
- `NotifyWindowClosed()`: 윈도우 종료 알림

**상속 클래스**:
- `AttackerInputHandler`: 공격자 입력 처리
- `DefenderInputHandler`: 방어자 입력 처리 (막기 시스템 포함)

## 전투 흐름도

### 전투 시작부터 종료까지

| 단계 | 클래스/메서드 | 주요 작업 | 다음 단계 |
|------|--------------|----------|----------|
| **1. 전투 시작** | `CombatManager.StartBattle()` | - CombatCharacterManager 초기화<br>- 슬롯 생성 및 Character 바인딩<br>- Actor 생성 및 배치<br>- Controller 생성 및 바인딩<br>- InputHandler 생성 및 바인딩<br>- BattleState 초기화<br>- BattleExecutor 생성 | → 2. 전투 루프 |
| **2. 전투 루프** | `BattleExecutor.RunBattle()` (코루틴) | while (!isBattleEnded) {<br>- TeamA 턴 준비<br>- PerformTurn(TeamA)<br>- TeamB 턴 준비<br>- PerformTurn(TeamB)<br>- ResetNPCProbabilities()<br>} | → 3. 턴 수행 |
| **3. 턴 수행** | `BattleExecutor.PerformTurn()` | 1. 턴 컨텍스트 생성<br>2. Controller에서 커맨드 선택<br>3. InputHandler 바인딩<br>4. 애니메이션 재생<br>5. 히트별 처리<br>6. 모든 히트 판정 완료 대기<br>7. 피해량 계산<br>8. 전투 종료 체크 | → 4. 종료 체크 또는 2. 전투 루프 |
| **4. 종료 체크** | `BattleExecutor` | - HP <= 0 체크<br>- isBattleEnded 플래그 설정 | → 5. 전투 종료 또는 2. 전투 루프 |
| **5. 전투 종료** | `CombatManager.EndBattle()` | - 전투 결과 처리<br>- Scene 전환 | 종료 |

### 턴 수행 상세 흐름

| 단계 | 작업 내용 | 관련 클래스/메서드 | 출력/결과 |
|------|----------|-------------------|----------|
| **1. 턴 컨텍스트 생성** | - 공격자/방어자 슬롯 결정<br>- Controller 참조 설정<br>- CombatTurnContext 생성 | `BattleExecutor.PrepareTeamTurn()`<br>`CombatTurnContext` | 턴 컨텍스트 객체 |
| **2. 커맨드 선택** | - Controller에서 커맨드 선택<br>- PlayerController: UI 선택<br>- AIController: BT 기반 선택 | `ICombatController.GetSelectedCommand()`<br>`PlayerController` / `AIController` | 선택된 커맨드 데이터 |
| **3. InputHandler 바인딩** | - 공격자/방어자 InputHandler 바인딩<br>- 슬롯 정보 전달 | `CombatManager.BindInputHandler()`<br>`AttackerInputHandler`<br>`DefenderInputHandler` | 바인딩 완료 |
| **4. 애니메이션 재생** | - 공격 커맨드 애니메이션 재생 | `ICombatController.OnPlayActionCommand()` | 애니메이션 재생 시작 |
| **5. 히트별 처리** | for each hit in command.hits {<br>- PerfectTimingWindow 설정<br>- 입력 대기<br>- 판정 처리<br>- 결과 표시<br>} | `BaseInputHandler.RegisterHitTiming()`<br>`BaseInputHandler.HasPerfectInput()` | 히트별 판정 결과 |
| **6. 판정 완료 대기** | - 모든 히트의 판정 완료 대기 | `BattleExecutor.EnsureAllHitJudgmentsCompleted()` | 모든 판정 완료 |
| **7. 피해량 계산** | - HP 감소<br>- Poise 감소<br>- 전투 종료 체크 | `BattleExecutor.ProcessDamageCalculation()` | 피해량 적용, 전투 종료 여부 |
| **8. 턴 완료** | - 턴 종료 처리 | - | 다음 턴 또는 전투 종료 |

## 주요 설계 결정사항

### 1. 슬롯 기반 시스템
**결정**: `CombatantSlot`을 통한 통합 관리

**이유**:
- Player/NPC 구분 없이 통합 처리 가능
- 코드 중복 제거
- 확장성 확보 (향후 다대다 전투 대비)

**영향**:
- 모든 전투 로직이 슬롯 기반으로 동작
- `isPlayer` 같은 플래그 제거

---

### 2. BattleExecutor 분리
**결정**: 전투 실행 로직을 별도 파일로 분리

**이유**:
- `CombatManager`의 코드량 감소 (2000+ 줄 → 관리 가능한 크기)
- 책임 분리: 상태 관리 vs 실행 로직
- 코드 가독성 및 유지보수성 향상

**영향**:
- `CombatManager`의 많은 멤버가 `internal`로 변경
- `BattleExecutor`는 `CombatManager`의 `internal` 멤버에 접근

---

### 3. BattleState 중첩 클래스
**결정**: `BattleState`를 `CombatManager` 내부 중첩 클래스로 유지

**이유**:
- 전투 상태의 단일 소스(Single Source of Truth)
- `CombatManager`와 밀접한 관계
- 접근성 제어 용이 (`internal`)

**영향**:
- `BattleExecutor`에서 `BattleState` 접근 가능 (`internal`)
- 외부에서는 `CombatManager`를 통해서만 접근

---

### 4. ICombatController 인터페이스
**결정**: 플레이어/AI 컨트롤러를 인터페이스로 통합

**이유**:
- 플레이어/AI 구분 없이 동일한 인터페이스 사용
- 확장성 확보 (향후 다른 컨트롤러 타입 추가 가능)

**영향**:
- `PlayerController`와 `AIController`가 동일한 인터페이스 구현
- 슬롯에 바인딩된 컨트롤러 타입에 관계없이 동일한 방식으로 사용
