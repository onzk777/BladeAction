## 📅 구현 단계

### 1단계: 1:1 일반화 (NPC vs NPC 지원) [진행도 90%]

**목표:** PlayerCharacter/EnemyCharacter → Combatant1/Combatant2

**진행 현황**
- 완료: 슬롯 기반 공격/방어 입력 핸들러 정비, NPC vs NPC 전투 루프 검증 (발사체 충돌, BT 기반 방어 동작), CombatCharacterManager 슬롯 구조 안정화
- 진행 중: HUD/디버그 패널 실시간 스테이터스 갱신 (HPPanel TeamA/TeamB 전환 완료), ControlType 명칭 적용 및 슬롯 제어 방식 정비

#### 작업 항목

| 작업 | 파일 | 내용 |
|------|------|------|
| CombatCharacterManager 수정 | CombatCharacterManager.cs | PlayerCharacter/CurrentEnemy → Combatant1/2 |
| GetCharacter 로직 추가 | CombatCharacterManager.cs | Player/NPC 구분 조회 |
| AIController 생성 | Controller/AIController.cs | EnemyController 복사 → BT 기반 |
| PlayerController 수정 | Controller/PlayerController.cs | 변경 사항 없음 (이미 일반화됨) |
| CombatManager 수정 | Combat/CombatManager.cs | PlayerCharacter → Combatant1 참조 변경 |

#### 검증

```
TestScene에서:
- "Player" vs "Enemy1" → 정상 동작
- "NPC_A" vs "NPC_B" → BT vs BT 전투 동작
```

**예상 시간: 6-8시간**

**참고:** 승패 판정 규칙은 아직 적용 안 함 (3단계에서 적용)

---

### 2단계: Battle 클래스 분리 [진행도 30%]

**목표:** 전투 로직을 Battle과 BattleExecutor로 분리

**진행 현황**
- `RunCombat`의 팀별 턴 흐름을 `PrepareTeamTurn()`으로 분리함 (BattleExecutor 이관 대비)
- 전투 수행/판정 관련 메서드 및 필드 의존성 인벤토리 작성 완료
- CombatManager 내부에 BattleState 중첩 클래스 도입 → 턴 컨텍스트/입력/히트 판정 상태를 BattleState가 소유하도록 이전
- BattleState를 별도 파일로 분리할 준비 완료 (ControlType 적용, 상태 접근자 정리됨)
- 예정: 기존 턴/판정 로직을 `Battle`/`BattleExecutor`로 단계적 이전 (UI 의존성 주입 설계 포함)

#### 작업 항목

| 작업 | 파일 | 내용 |
|------|------|------|
| Battle 클래스 생성 | Combat/Battle.cs | 전투 관리 클래스 |
| BattleExecutor 생성 | Combat/BattleExecutor.cs | CombatManager 로직 복사 |
| CombatManager 수정 | Combat/CombatManager.cs | Battle 생성 및 실행으로 변경 |
| 테스트 | - | 1:1 전투 동작 확인 |

#### 리팩토링 범위

```
CombatManager (Before)
├─ RunCombat()
├─ PerformTurn()
├─ CalculateDamage()
└─ ... (2000+ 라인)

↓ 분리

Battle (After)
├─ Initialize()
├─ Run()
└─ DetermineVictor()

BattleExecutor (After)
├─ RunBattle()
├─ PerformTurn()
└─ CalculateDamage()
```

**예상 시간: 4-6시간**

### 3단계: CombatSessionManager 구현 (다대다 지원) [진행도 0%]

**목표:** 다대다 전투 지원 + 승패 판정 규칙 적용

**진행 현황**
- 예정: Session 관리, 즉시 승패 판정, 재매칭 로직 구현
- 선행 조건: 2단계 Battle 구조 정리 완료

#### 작업 항목

| 작업 | 파일 | 내용 |
|------|------|------|
| CombatSessionManager 생성 | Combat/CombatSessionManager.cs | Session 관리 클래스 |
| SessionResult 구조 | Combat/SessionResult.cs | 결과 데이터 구조 + VictoryReason/DefeatReason |
| 매칭 알고리즘 | CombatSessionManager.cs | 엔트리 순서 기반 매칭 (선두 우선) |
| **승패 판정 규칙** ⭐ | CombatSessionManager.cs | 선두 전투 불능 시 즉시 종료 |
| 재매칭 로직 | CombatSessionManager.cs | Reserve 투입 |
| Battle 중단 처리 | Battle.cs | 즉시 종료 시 진행 중 Battle 중단 |
| TestScene 통합 | Scene/TestSceneManager.cs | 팀 구성 UI 추가 (향후) |

#### 핵심 구현 요소

**1. 즉시 승패 판정 (필수):**
- `CheckImmediateVictoryOrDefeat()` 메서드
- teamA[0] (플레이어) 전투 불능 → 즉시 패배
- teamB[0] (보스) 전투 불능 → 즉시 승리
- 진행 중인 모든 Battle 중단

**2. 엔트리 순서 관리 (필수):**
- List 순서 = 엔트리 순서
- 절대 정렬/셔플 금지
- 선두(index 0) 고정

**3. 매칭 알고리즘 (필수):**
- Sequential Matching (순차 매칭)
- 재매칭 로직
- Reserve 관리

**예상 시간: 6-8시간**

---

### 4단계: View 시스템 구현 [진행도 0%]

**목표:** Main/Sub Battle 화면 구성

**진행 현황**
- 예정: Main/Sub 전투 뷰 분리 및 RenderTexture 구성
- 선행 조건: 3단계 Session 흐름 확정 후 진행

#### 작업 항목

| 작업 | 파일 | 내용 |
|------|------|------|
| IBattleView 인터페이스 | UI/IBattleView.cs | View 인터페이스 |
| MainBattleView | UI/MainBattleView.cs | 전체 화면 표시 |
| SubBattleView | UI/SubBattleView.cs | 작은 화면 표시 |
| Camera 설정 | CombatScene | Main/Sub Camera 배치 |
| RenderTexture 설정 | Unity | Sub Battle용 RenderTexture |

#### 화면 구성

```
MainBattleView (기존 활용)
└─ 현재 CombatScene 화면 그대로 사용

SubBattleView (신규)
├─ RenderTexture로 작은 화면 렌더링
├─ UI 간소화 (HP 바만 표시)
└─ 화면 하단/측면 배치
```

**예상 시간: 4-6시간**

## 우선순위

### 필수 (MVP)

1. ✅ **1단계: 1:1 일반화** (NPC vs NPC 지원, HUD/디버그 후속 작업 진행 중)
2. ⏳ **3단계: 다대다 기본** (Battle 분리 후 착수 예정)

### 중요 (기능 완성)

3. ⏳ **2단계: Battle 분리**
   - 코드 구조 개선
   - 확장성 확보
4. ⏳ **4단계: View 시스템**
   - Main/Sub 화면 구분
   - 사용자 경험 향상

### 선택 (향후 확장)

5. 🔮 **최적화**
   - Battle Pool
   - Controller Pool

6. 🔮 **고급 매칭**
   - Optimal Matching
   - Custom Strategy

7. 🔮 **Reserve 패시브 능력** (우선순위: 낮음)
   - 대기 멤버의 패시브 지원 시스템
   - 쳐내기 지원, 긴급 회복, 응원, 견제 등
   - **구현 시점:** 기본 시스템 완성 후

| 위험 | 영향 | 대응 |

## 테스트 시나리오

### 시나리오 1: 단순 2 vs 2

```
TeamA: [Player, NPC_A1]
TeamB: [NPC_B1, NPC_B2]

예상 결과:
- Battle 1 (Main): Player vs NPC_B1
- Battle 2 (Sub):  NPC_A1 vs NPC_B2
- 동시 진행
- 둘 중 하나 먼저 종료
- 모두 종료 시 Session 종료
```

---

### 시나리오 2: 불균형 3 vs 2

```
TeamA: [Player, NPC_A1, NPC_A2]
TeamB: [NPC_B1, NPC_B2]

초기 매칭:
- Battle 1: Player vs NPC_B1
- Battle 2: NPC_A1 vs NPC_B2
- Reserve: [NPC_A2]

Battle 2 종료 (NPC_B2 승리):
- Battle 1: 계속
- Battle 3: NPC_A2 vs NPC_B2 (재매칭)

예상 결과:
- 재매칭 정상 동작
- Reserve 자동 투입
```

---

### 시나리오 3: 완전 NPC 전투

```
TeamA: [NPC_A1, NPC_A2]
TeamB: [NPC_B1, NPC_B2]

예상 결과:
- Battle 1: NPC_A1 vs NPC_B1 (Main) ← Player 없으면 첫 Battle이 Main
- Battle 2: NPC_A2 vs NPC_B2 (Sub)
- BT vs BT 자동 진행
- 관전 모드
```

### 시나리오 4: 즉시 승패 판정 테스트 ⭐

**Case A: 플레이어 전투 불능**
```
TeamA: [Player, Ally1, Ally2]
TeamB: [Boss, Sub1, Sub2]

초기:
- Battle 1 (Main): Player vs Boss
- Battle 2 (Sub):  Ally1 vs Sub1
- Battle 3 (Sub):  Ally2 vs Sub2

진행:
- Battle 2: Ally1 승리! (Sub1 패배)
- Battle 3: 진행 중...
- Battle 1: Player HP 0! ← 플레이어 전투 불능!

예상 결과:
✅ Battle 1 종료 시점에 즉시 패배!
✅ Battle 3 강제 중단!
✅ Session 즉시 종료
✅ DefeatReason: PlayerDown
```

**Case B: 보스 전투 불능**
```
TeamA: [Player, Ally1]
TeamB: [Boss, Sub1, Sub2]

초기:
- Battle 1 (Main): Player vs Boss
- Battle 2 (Sub):  Ally1 vs Sub1
- Reserve B: Sub2

진행:
- Battle 2: Ally1 패배! (Sub1 승리)
- Battle 3 (신규): Sub1 vs Sub2 (재매칭)
- Battle 1: Boss HP 0! ← 보스 전투 불능!

예상 결과:
✅ Battle 1 종료 시점에 즉시 승리!
✅ Battle 3 강제 중단!
✅ Session 즉시 종료
✅ VictoryReason: BossDefeated
✅ Sub1, Sub2가 살아있어도 승리!
```
