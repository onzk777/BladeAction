## 시스템 개요

### 목적

**다대다 전투 지원**
- 1:1부터 N:M까지 확장 가능
- 여러 Battle 동시 진행
- 엔트리 순서 기반 매칭
- 선두 중심 승패 판정

---

### 3-Layer 구조

```
CombatSessionManager
  └─ 전체 전투 세션 관리
     └─ Battle (1개 이상)
        └─ BattleExecutor
           └─ 턴제 전투 로직 실행
```

## 구성 요소 사양

### 1. CombatSessionManager

**타입**: MonoBehaviour Singleton  
**위치**: CombatScene  
**생명주기**: CombatScene 로드 ~ 언로드

#### 역할

| 역할 | 설명 |
|------|------|
| **팀 관리** | 양측 팀 Character 목록 관리, 엔트리 순서 유지 |
| **매칭** | 1:1 Battle 생성, 엔트리 순서 기반 매칭 |
| **재매칭** | Battle 종료 시 Reserve 투입, 새 Battle 생성 |
| **승패 판정** | 선두 전투 불능 확인, 즉시 종료 처리 |
| **보상 계산** | Session 종료 시 보상 산정 |

---

#### 주요 데이터

| 필드 | 타입 | 설명 |
|------|------|------|
| `teamA` | `List<Character>` | A팀 멤버 (엔트리 순서 유지, [0]=선두) |
| `teamB` | `List<Character>` | B팀 멤버 (엔트리 순서 유지, [0]=선두) |
| `activeBattles` | `List<Battle>` | 진행 중인 Battle 목록 |
| `reserveA` | `Queue<Character>` | A팀 대기 인원 |
| `reserveB` | `Queue<Character>` | B팀 대기 인원 |
| `state` | `SessionState` | Session 상태 (Idle/Preparing/Running/Completed) |
| `result` | `SessionResult` | Session 결과 |

---

#### 핵심 동작

**1. 초기 매칭**
- 엔트리 순서대로 1:1 매칭
- `teamA[0] vs teamB[0]` = 첫 Battle (항상 Main)
- 남은 인원은 Reserve로

**2. 승패 판정 (즉시 종료 규칙)**
- `teamA[0]` (플레이어) 전투 불능 → 즉시 패배
- `teamB[0]` (보스) 전투 불능 → 즉시 승리
- 일반 멤버 패배 → 재매칭 계속

**3. 재매칭**
- 승자 확인
- 패배 팀 Reserve에서 투입
- 새 Battle 생성 및 시작

---

### 2. Battle

**타입**: 일반 클래스 (MonoBehaviour 아님)  
**생명주기**: Session 내에서 생성 ~ 완료 시 소멸

#### 역할

| 역할 | 설명 |
|------|------|
| **전투자 관리** | 2명의 Character 참조 유지 |
| **Controller 연결** | Player 입력 또는 AI Controller 연결 |
| **실행 제어** | BattleExecutor 생성 및 실행 관리 |
| **승패 판정** | HP 기반 승자/패자 결정 |
| **결과 보고** | Session에게 결과 전달 (이벤트) |

---

#### 주요 데이터

| 필드 | 타입 | 설명 |
|------|------|------|
| `BattleId` | `string` | Battle 식별자 |
| `Combatant1` | `Character` | 첫 번째 전투자 |
| `Combatant2` | `Character` | 두 번째 전투자 |
| `Controller1` | `ICombatController` | Combatant1 컨트롤러 |
| `Controller2` | `ICombatController` | Combatant2 컨트롤러 |
| `ViewType` | `BattleViewType` | Main/Sub 화면 타입 |
| `State` | `BattleState` | Battle 상태 |
| `Result` | `BattleResult` | Battle 결과 |

---

#### 핵심 동작

**1. Controller 생성**
- `PlayerCharacter` → Scene에서 PlayerController 찾기
- 그 외 → AIController 동적 생성

**2. 전투 실행**
- BattleExecutor에게 위임
- Coroutine으로 턴제 진행

**3. 승패 판정**
- HP 0 확인
- Winner/Loser 결정

---

### 3. BattleExecutor

**타입**: 일반 클래스  
**생명주기**: Battle와 동일

#### 역할

| 역할 | 설명 |
|------|------|
| **턴제 로직** | 공격/방어 턴 반복 실행 |
| **타이밍 처리** | AttackerInputHandler, DefenderInputHandler 제어 |
| **데미지 계산** | 공격력, 방어력, 크리티컬 등 계산 |
| **애니메이션** | Controller를 통한 애니메이션 트리거 |
| **HP 업데이트** | Character HP 변경 및 UI 갱신 |

---

#### 현재 CombatManager와의 관계

**로직 이동:**
- `CombatManager.RunCombat()` → `BattleExecutor.RunBattle()`
- `CombatManager.PerformTurn()` → `BattleExecutor.PerformTurn()`
- `CombatManager.CalculateDamage()` → `BattleExecutor.CalculateDamage()`

**참조 변경:**
- `CombatCharacterManager.PlayerCharacter` → `battle.Combatant1`
- `CombatCharacterManager.CurrentEnemy` → `battle.Combatant2`
- `playerController` → `battle.Controller1`
- `enemyController` → `battle.Controller2`

**기존 로직 재사용:** 대부분 그대로 사용 가능

---

### 4. AIController

**타입**: MonoBehaviour  
**인터페이스**: `ICombatController`  
**역할**: NPC 전투 제어 (BT 기반)

#### 사양

| 속성 | 값 |
|------|-----|
| **입력 소스** | `Character.ChooseCommand()` (BT 실행) |
| **애니메이션** | Spine SkeletonMecanim 제어 |
| **기반 구현** | EnemyController 복사 후 일반화 |

### Enum 정의

**SessionState:**
- `Idle`: 대기
- `Preparing`: 준비 중 (매칭)
- `Running`: 진행 중
- `Completed`: 완료

**BattleState:**
- `Preparing`: 준비

**BattleViewType:**
- `Main`: 메인 카메라 (전체 화면)

## 동작 원리

### 1. Session 시작 흐름

```
입력: Team A IDs, Team B IDs
  ↓
GetCharacters() - Character 인스턴스 조회
  ├─ Player ID → PlayerCharacterManager
  └─ NPC ID → NonPlayerCharacterManager
  ↓
CreateInitialMatchups() - 엔트리 순서 기반 매칭
  ├─ teamA[0] vs teamB[0] → Battle #1 (Main, 선두)
  ├─ teamA[1] vs teamB[1] → Battle #2 (Sub)
  └─ 남은 인원 → Reserve
  ↓
CreateBattle() - Battle 인스턴스 생성 (각 매칭마다)
  ├─ Controller 연결
  └─ Executor 생성
  ↓
StartAllBattles() - Coroutine으로 동시 실행
```

---

### 2. Battle 진행 흐름

```
Battle.Run()
  ↓
BattleExecutor.RunBattle()
  ↓
while (!BattleOver)
  ├─ PerformTurn() - 턴 수행
  │  ├─ 검술 선택 (Controller)
  │  ├─ 애니메이션 재생
  │  ├─ 타이밍 입력
  │  ├─ 데미지 계산
  │  └─ HP 업데이트
  └─ 다음 턴
  ↓
DetermineVictor() - HP 0 확인, 승자 결정
  ↓
OnBattleComplete 이벤트 발생
```

---

### 3. 승패 판정 흐름 ⭐

```
Battle 종료
  ↓
OnBattleComplete(battle)
  ↓
CheckImmediateVictoryOrDefeat() - 즉시 종료 확인
  ├─ loser == teamA[0]? → 플레이어 전투 불능 → 즉시 패배!
  ├─ loser == teamB[0]? → 보스 전투 불능 → 즉시 승리!
  └─ 일반 멤버? → 계속 진행
  ↓
즉시 종료가 아니면:
  ├─ 패배자 제거
  ├─ TryRematch() - Reserve 투입
  └─ IsSessionOver() - 전체 종료 확인
```

**즉시 종료 규칙:**
- **플레이어 (teamA[0]) 전투 불능** → 모든 Battle 중단, 즉시 패배
- **보스 (teamB[0]) 전투 불능** → 모든 Battle 중단, 즉시 승리

---

### 4. 재매칭 흐름

```
Battle 종료 (승자: Winner, 패자: Loser)
  ↓
승자 팀 확인 (teamA? teamB?)
  ↓
패배 팀 Reserve 확인
  ├─ Reserve > 0 → 다음 Character Dequeue
  │  ├─ 새 Matchup 생성 (Winner vs Reserve Member)
  │  ├─ ViewType 결정 (Player 포함 시 Main)
  │  └─ 새 Battle 생성 및 시작
  └─ Reserve == 0 → 재매칭 없음
```

## 매칭 알고리즘 사양

### Sequential Matching (기본)

**입력:** teamA (N명), teamB (M명)

**처리:**
1. `matchCount = min(N, M)`
2. `for i in 0..matchCount:`
   - `matchup[i] = teamA[i] vs teamB[i]`
   - `if i == 0: viewType = Main` (선두는 항상 Main)
   - `else: viewType = Sub`
3. 남은 인원 → Reserve

**출력:** Matchup 목록, Reserve 목록

---

### 재매칭 알고리즘

**입력:** Winner (Character), Reserve (Queue)

**처리:**
1. Winner 팀 확인 (A? B?)
2. 상대 팀 Reserve 확인
3. `if Reserve.Count > 0:`
   - `next = Reserve.Dequeue()`
   - `matchup = Winner vs next`
   - `viewType = Player 포함? Main : Sub`
   - Battle 생성 및 시작
4. `else: 재매칭 없음`

## 구현 고려사항

### 1. 엔트리 순서 보장

**중요:** List의 순서가 곧 엔트리 순서

- `teamA[0]`은 항상 플레이어
- `teamB[0]`은 항상 보스
- **절대 정렬하지 말 것**
- **절대 셔플하지 말 것**

---

### 2. 즉시 종료 처리

**선두 전투 불능 시:**
1. 즉시 `StopAllActiveBattles()` 호출
2. 진행 중인 다른 Battle 모두 중단
3. `FinalizeSession()` 즉시 호출
4. **재매칭 하지 않음**

---

### 3. Battle 독립성

**Battle은 Session을 몰라도 됨:**
- Battle은 자신의 2명만 관리
- Session 상태 참조 안 함
- 결과만 이벤트로 보고

**장점:**
- Battle 재사용 가능
- 테스트 용이
- 확장성 확보

---

### 4. Controller 생명주기

**PlayerController:**
- CombatScene에 미리 배치 (GameObject)
- Battle이 찾아서 사용
- Scene 언로드 시 함께 파괴

**AIController:**
- Battle 생성 시 동적 생성 (GameObject)
- Battle 종료 시 파괴 또는 Pool 반환
- 재사용 고려 (성능)

---

### 5. Character 참조 방식

**직접 소유 안 함:**
- Session: Character 참조만 (Manager에서 가져옴)
- Battle: Character 참조만 (Session에서 받음)
- Executor: Character 참조만 (Battle에서 받음)

**실제 인스턴스 소유:**
- `PlayerCharacterManager.PlayerCharacter` (영속)
- `NonPlayerCharacterManager` Dictionary (영속)

**구성:**
- Combatant 위치: 축소된 Anchor
- UI: 간소화 (HP 바만)
- RenderTexture로 렌더링 → UI Image에 표시

## 확장성 고려사항

### 1단계 → 2단계 확장

**1단계 (1:1 일반화):**
- CombatCharacterManager: Combatant1, Combatant2
- Battle 없음 (CombatManager가 직접 실행)

**2단계 (Battle 분리):**
- Battle 클래스 추가
- Executor 분리
- **기존 로직 재사용**

---

### 2단계 → 3단계 확장

**2단계 (Battle 분리):**
- 1개 Battle 실행

**3단계 (다대다):**
- CombatSessionManager 추가
- 여러 Battle 생성
- **Battle 로직 재사용**

## Reserve 패시브 사양 (우선순위: 낮음)

### 시스템 개요

**용도**: 대기 중인 멤버가 전장에 영향

**발동 타이밍**: 매 턴 시작 시

**발동 확률**: 패시브 능력별로 정의 (10-30%)

---

### 패시브 능력 타입

| 능력 | 조건 | 효과 |
|------|------|------|

## 기존 시스템과의 통합

### CombatCharacterManager 변경 사양

**Before:**
```
PlayerCharacter PlayerCharacter
EnemyCharacter CurrentEnemy
```

**After:**
```
Character Combatant1
Character Combatant2
```

**메서드:**
- `InitializeBattle(char1Id, char2Id)` - ID로 Character 조회

### SceneFlowController 변경 사양

**기존:**
```
StartCombat(playerId, enemyId) - 1:1 전투
```

**확장:**
```
StartCombatFlow(teamAIds, teamBIds) - 다대다 전투
```

**static 필드 사용:**
- CombatScene 로드 전에 데이터 저장
- CombatSessionManager.StartSession()에서 사용

## 구현 제약사항

### 엄수 사항

1. **엔트리 순서 절대 유지**
   - teamA[0], teamB[0]은 선두 고정
   - 정렬, 셔플 금지

2. **즉시 종료 우선**
   - 선두 전투 불능 확인은 최우선
   - 다른 Battle 상태 무시하고 즉시 종료

3. **Battle 독립성**
   - Battle은 Session 참조 안 함
   - 이벤트로만 통신

---

### 권장 사항

1. **Controller Pool 사용**
   - AIController 재사용으로 GC 감소

2. **Battle 수 제한**
   - 최대 4개 (성능)

3. **에러 처리**
   - Character 조회 실패 시 Fallback 또는 Exception

## 테스트 사양

### 필수 테스트 케이스

| 케이스 | 팀 구성 | 예상 결과 |
|--------|---------|----------|
| **단순 1:1** | [Player] vs [Boss] | Main Battle 1개, 정상 동작 |
| **균형 2:2** | [Player, Ally] vs [Boss, Sub] | Main 1개 + Sub 1개, 동시 진행 |
| **불균형 3:2** | [Player, A1, A2] vs [Boss, B1] | Main 1개 + Sub 1개, Reserve 투입 |
| **플레이어 패배** | Player HP 0 | 즉시 패배, 다른 Battle 중단 |
| **보스 패배** | Boss HP 0 | 즉시 승리, 다른 Battle 중단 |
| **NPC only** | [NPC1, NPC2] vs [NPC3, NPC4] | Player 없어도 동작 |
