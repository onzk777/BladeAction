# 아이템 시스템 구현 계획서

## 문서 목적
이 문서는 아이템 시스템의 구현 순서와 각 단계별 상세 작업 내용을 정의합니다. 탑다운 방식으로 핵심 코어 모듈을 우선 구현하여 안정적인 시스템 구축을 목표로 합니다.

---

## 시스템 아키텍처 개요

### 계층 구조 (Hierarchy)
```
Layer 1: 타입 시스템 (ScriptableObject)
    ├── WeaponTypeData
    ├── ArmorTypeData
    ├── AccessoryTypeData
    └── SwordplayStyleData
         ↓
Layer 2: 스탯 및 데이터 시스템
    ├── EquipmentStats (구조체)
    ├── StatTable (ScriptableObject)
    └── StatDatabase (중앙 관리)
         ↓
Layer 3: 아이템 데이터 시스템
    ├── ItemData (하이브리드 구조)
    └── ItemDatabase (중앙 관리)
         ↓
Layer 4: Excel 데이터 관리
    ├── CSV Importer
    ├── Data Mapper
    └── Validation System
         ↓
Layer 5: 인벤토리 코어
    ├── CombatantInventory
    ├── OwnedItem
    └── EquipmentSlot
         ↓
Layer 6: 인벤토리 매니저
    ├── InventoryManager (로직)
    ├── ItemEvents (이벤트)
    └── SaveData (저장/로드)
         ↓
Layer 7: UI 시스템
    ├── InventoryUI (메인 패널)
    ├── ItemSlotUI (개별 슬롯)
    ├── EquipmentSlotUI (장비 슬롯)
    └── ItemDetailPanel (정보 패널)
         ↓
Layer 8: 고급 기능
    ├── Filter & Sort
    ├── Drag & Drop
    └── Context Menu
```

### 핵심 설계 원칙
- **데이터 중심 설계**: ScriptableObject 기반 타입 시스템
- **하이브리드 데이터 관리**: Unity Asset (참조) + Excel (텍스트/수치)
- **명확한 책임 분리**: 데이터 / 로직 / UI 레이어 분리
- **확장성**: 새로운 아이템 타입 추가 용이
- **null 안전성**: 모든 참조에 대한 null 체크

## 주의사항

### 1. null 안전성
- 모든 Asset 참조는 null 체크 필수
- ItemData, Database 등 참조 시 항상 검증

### 2. 성능 고려
- 대량 아이템 처리 시 최적화 필요
- UI 갱신은 필요할 때만 수행
- 필터링/정렬은 LINQ 최적화 고려

### 3. 확장성
- 새로운 타입 추가 용이하도록 설계
- Excel 포맷 변경에 유연하게 대응
- UI 레이아웃 변경 용이하도록

### 4. 데이터 일관성
- Excel과 Unity Asset 동기화 중요
- itemKey 중복 체크 필수
- 참조 무결성 보장

### 5. UI 최적화
- 화면에 보이는 아이템만 렌더링 (가상화)
- 오브젝트 풀링 고려
- TextMeshPro 최적화 설정
